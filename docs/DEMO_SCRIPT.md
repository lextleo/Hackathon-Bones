# Demo script

> Aim for a demo that is understandable without narration and recoverable if the network, hardware, or model misbehaves.

## 3-minute walkthrough

| Time | Show | Say |
| --- | --- | --- |
| 0:00–0:20 | The user and the pain | “Today, [user] has to [current workaround].” |
| 0:20–0:45 | The product and its promise | “We built [solution] to [outcome].” |
| 0:45–1:50 | The core flow, live | Show the smallest complete path. Avoid explaining every button. |
| 1:50–2:20 | Evidence | Show a metric, comparison, test result, or user feedback. |
| 2:20–2:45 | Why this approach | Explain one important technical choice or differentiator. |
| 2:45–3:00 | Limits and next step | State the current limitation and what you would validate next. |

## Demo preflight

- [ ] Restart the app/device and run the flow from the beginning.
- [ ] Seed known-good sample data.
- [ ] Verify Wi-Fi, API keys, ports, battery, permissions, and dependencies.
- [ ] Close unrelated windows and turn off notifications.
- [ ] Prepare a short screen recording or screenshots as a fallback.
- [ ] Make sure the presenter can explain what is real, mocked, or simulated.
